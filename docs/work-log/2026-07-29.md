## Token drag flicker investigation

- Follow-up objective: stop player and DM tokens from jumping to unrelated
  grid locations when a drag begins and prevent live synchronization from
  fighting local movement.
- Baseline commit: `68d46d2b803667c803e590465a4027240fba2edf`.
- Branch: `codex/first-edition-mapping`.
- Upstream comparison: zero commits ahead and zero behind; `git fetch
  origin --prune` was attempted, but the managed workspace again blocked
  `.git/FETCH_HEAD`.
- Pre-existing changes: none.
- Root-cause findings:
  - every token's pointer-down handler immediately calls the movement
    calculator with the token button as `event.currentTarget`;
  - the calculator assumes `event.currentTarget` is the full grid, so the
    initial press divides the token's tiny rectangle into grid cells and
    generates a false distant position;
  - the following bubbled grid movement uses the correct rectangle, producing
    the visible jump/flicker;
  - player movement also publishes on every pointer-move event, producing
    unnecessary overlapping live table writes even when the token remains in
    the same quadrant.
- Planned correction:
  - pointer-down starts dragging but never recalculates position;
  - only grid pointer movement calculates coordinates;
  - update the player token locally and smoothly while dragging;
  - debounce live persistence and flush the final position on pointer-up or
    pointer-leave;
  - apply the initial-coordinate correction to both player and DM tokens.
- Planned verification: regression coverage for drag start, local movement,
  debounced persistence, final-position flush, full frontend tests, production
  build, and `git diff --check`.
- Completed:
  - player, marching-order, and monster tokens now begin dragging without
    calculating a position from the token button;
  - all coordinates are calculated only from pointer movement over the full
    grid;
  - repeated movement within the same quadrant no longer creates redundant
    DM-side state updates;
  - player movement updates locally during the drag, debounces remote saves,
    and flushes the final position on pointer-up or pointer-leave;
  - pending player movement is discarded if the session closes.
