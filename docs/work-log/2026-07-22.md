## Decisions

- Use the same operating-memory pattern as ValveIO: progress summary, daily
  work log, mandatory deployment runbook, live inventory, and per-deployment
  evidence.
- Do not begin Mapping Mode application code until this operating foundation is
  complete and validated.
- Do not deploy while the live server inventory is unverified.
- Treat the source-book consolidation deletion as pre-existing work and keep it
  distinct in the log.
- Mapping portal ownership was clarified after the initial documentation pass:
  the DM portal controls active mode and active map only. The Mapper editor,
  synchronized viewer, and player map library belong exclusively on the
  authenticated Classic player portal.
- Mapping state will be stored as structured JSON on campaign map records with a
  monotonically increasing revision. Player updates require both campaign
  membership and assignment as that map's Mapper.
- The first synchronization pass will use durable server saves and periodic
  viewer refresh. WebSocket or server-sent push is deliberately deferred until
  persistence, authorization, and the editing model are verified.
