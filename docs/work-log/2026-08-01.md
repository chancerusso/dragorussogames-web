## Correct procedure for public main-website changes

This is the required quick workflow for future changes to the root public website. The public homepage is a static Cloudflare Pages site. It is separate from Drago Table, the DM portal, Classic/player portal, FastAPI backend, databases, Foundry, and the VPS-hosted applications.

### 1. Keep the change frontend-only

- For campaign-card text, links, schedules, and artwork, normally change only root `index.html` and the required file under root `assets/`.
- Do not inspect, edit, stage, build, upload, or deploy `backend/`, `frontend/` (the Drago Table React application), databases, migrations, private references, Foundry modules, or VPS services.
- Preserve all unrelated dirty-worktree files. Stage exact filenames, never `git add .`.

### 2. Verify the small change locally

- Parse `index.html` and confirm the expected card codes, links, labels, and image paths.
- Confirm every new image exists and loads.
- Check desktop and mobile card layout when the change affects presentation.
- Run `git diff --check`.
- Confirm the diff contains only the requested homepage files, new public assets, and the dated work-log entry.

### 3. Commit and push the exact website files

- Stage only the changed website files and the work log.
- Commit on the working branch and push that branch.
- Fast-forward the exact verified commit to `origin/main`; never force-push.
- Record the full commit SHA.
- Remember: a Git push is source control, not proof of deployment.

### 4. Publish to the correct Cloudflare Pages project

- Project: `dragorussogames-web`.
- Production branch: `main`.
- Do not deploy the repository root. It contains backend, development, private, and unrelated application files.
- Do not upload only `index.html`: a Cloudflare Pages deployment is a complete immutable website snapshot, so a one-file upload would remove the other public routes from that deployment.
- Build a clean public snapshot from the exact committed SHA, including the existing public routes unchanged and excluding backend/development/private material. The snapshot is packaging only; it does not mean those unchanged pages were edited.
- Deploy that clean directory with:

  `npx wrangler pages deploy <clean-public-directory> --project-name dragorussogames-web --branch main --commit-hash <full-commit-sha> --commit-message "<description>"`

- Never reuse an older `/private/tmp/` package after another commit. Create a new package from the new exact SHA so new artwork and edits are present.

### 5. Verify production before saying it is done

- Wait for Wrangler to report a successful deployment and deployment URL.
- Open `https://www.dragorussogames.com/` and hard-refresh.
- Confirm the requested content and artwork are visible on the live homepage.
- Check the main public routes and the newly changed destinations.
- Only after those checks pass should the work log and user handoff say the website is published.

### Key lesson from this session

- The code changes themselves were small and correct.
- Time was lost by mixing deployment-safety investigation with the simple homepage task and by referring to unrelated public files in user-facing updates.
- Future homepage work should stay focused on the requested root website files. Explain the complete-snapshot requirement only when publishing, and do not describe unchanged packaged files as part of the feature change.
