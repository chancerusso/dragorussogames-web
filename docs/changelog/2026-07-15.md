# 2026-07-15 — Drago Table VTT Playtest Build

## Summary

Today moved Drago Table from a rough referee screen into a usable first VTT playtest build for the DM Portal and Classic Player Portal. The table now supports OSRIC monsters, compact encounters, tactical grids, shared player view, trackers, dice, XP rewards, player snippets, and a DM-controlled live-session gate.

The final play model is:

- DM can always prepare and save the table state.
- Players can see the saved table state.
- Players can interact only after the DM clicks Start Session.
- Stop Session returns the player view to saved/read-only mode.

## Deployment Notes

This build requires the VPS to:

1. Pull branch `codex-osric-monster-catalog`.
2. Run backend migration:
   - `alembic upgrade head`
3. Restart backend:
   - `sudo systemctl restart russo-backend`
4. Rebuild frontend with DM API base.
5. Rsync frontend `dist/` to:
   - `/var/www/dm.dragorussogames.com/`
   - `/var/www/classic.dragorussogames.com/`

## Ready For Playtest

The next test should be a real table flow:

- DM opens Drago Table.
- DM prepares grid, tracker, and monsters.
- DM clicks Start Session.
- Player opens Classic Player Portal table.
- Player chooses token color, adds token, moves token, and adjusts HP.
- DM adds monster, places it, damages it, marks it dead, and confirms XP appears.
- DM distributes XP.
- DM clicks Stop Session and confirms player controls lock while saved state remains visible.

If that loop works at the table, Drago Table VTT version 1 is ready for campaign play.
