# 2026-06-21 — DRG 1e Character Vault + DM Foundation

## Summary

Today moved the DRG 1e Character Vault from a working prototype into a deployable, RUSSO-backed site feature. The browser app now talks to the RUSSO FastAPI backend through a configurable API base, the backend allows the live Drago Russo Games origins through CORS, and the character sheet/edit experience was tightened into something much closer to table use.

The Character Vault received several rounds of usability hardening: compact sheet layout, clear View vs Edit behavior, quick edit as a modal, visible save/action feedback, better inventory actions, cleaner equipment labels, race-adjusted ability recalculation, improved weapon proficiency filtering, multiple readied weapons, armor/shield restrictions, load display, coin display, and dwarf saving throw handling.

The DM tools started as broad admin pages, then were corrected into a campaign-first direction. Initial DM routes and the equipment editor were added, then the information architecture was revised so `/1e/dm/` is the dashboard, `/1e/dm/campaigns/` is the campaign list, `/1e/dm/campaigns/:id/` is the main campaign workspace, and `/1e/dm/equipment/` is the catalog builder/editor. Player and character admin pages remain only as fallback shells and are no longer promoted in navigation.

The day closed with this log so tomorrow's session can start from the actual state of the website, backend, DM tooling, and deployment assumptions without reconstructing the whole chain from commit history.

## Character Vault

### Character Sheet Redesign

- Reworked the character sheet into a compact table-ready view.
- Reduced oversized AC/HP/Move cards into tighter summary/stat layouts.
- Moved Quick Edit out of the top sheet body.
- Added one compact Quick Edit button.
- Quick Edit now opens a modal/panel.
- Quick Edit supports HP, XP, coins, location, storage location, and notes.
- Save feedback now shows visible confirmation such as `Saved.`
- View Character and Edit Character are now separate concepts.
- Existing characters no longer show creation-only roll assignment history on the sheet.
- Ability scores display final scores only, with subtle base/racial context where needed.
- Full edit flow remains available for identity, ability scores, race, class, level, alignment, campaign state, equipment, spells, and notes.
- Equipment rows were cleaned up.
- Weapon actions were reduced to Equip, Unequip, Store, and Delete.
- Inventory grouping was improved across equipped, carried, stored, treasure, and not-carried states.
- `Band` was renamed to `Load`.
- Movement and encumbrance now show Move, Carried, Coins, and Load.
- Coin summary and coin weight are visible and persistent.
- Equipment labels such as `adventuring_gear` and `magic_item` are converted into readable labels.
- Rules links were moved toward contextual modal behavior instead of repeated inline `RULES` labels.

### Character Logic

- Race changes now immediately recalculate adjusted ability scores.
- Race detail display updates when race changes.
- Class eligibility warnings update with race/class changes.
- Constitution overflow in ability boxes was addressed with abbreviated score labels.
- Dwarf saving throw adjustments were implemented in the shared vault rules service.
- Dwarf save warnings were removed when automated adjustments are available.
- Equip restrictions were tightened:
  - only one armor equipped
  - only one shield equipped
  - multiple weapons can be equipped/readied
  - gear can be equipped where supported
- Inventory action buttons now stay on the current view/edit page and refresh data.
- Add, Save, Equip, Unequip, Store, and Delete actions now show feedback.
- Stored items require storage location handling.
- Safe Storage language was clarified to Storage Location / Personal Storage Location.
- Weapon proficiency choices exclude ammunition such as arrows, bolts, sling stones, bullets, and ammunition subtypes.
- Ability rolling now supports rolling six 4d6-drop-lowest scores and assigning them to abilities, with DM override available.

### Lessons Learned

- DM Players should not be a primary workflow.
- DM Characters should not be a primary workflow.
- The DM workflow should be campaign-first.
- The global Character Vault remains the character list.
- Players remain owners of characters, but DMs think in campaigns.
- Equipment creation and adventure-specific item management belongs on the DM side.
- Authentication will eventually determine whether the global Character Vault can show all characters to DMs.

## UI / UX Decisions

### Accepted

- Use `DRG 1e` as visible branding.
- Use `Table Rules` instead of broad `House Rules` phrasing on player-facing surfaces.
- No automatic role selection on player-facing forms.
- View Character is separate from Edit Character.
- Save and action confirmations are required.
- No giant inline Quick Edit block.
- No permanent ability roll history display on View Character.
- Rules references should be contextual, not repeated inline clutter.
- Item action feedback is part of the core UX.
- DM tools are honest about being unprotected until login exists.
- DM tools are campaign-first.

### Rejected

- Giant admin dashboards.
- Stacked vertical hero text.
- Player-first DM workflow.
- `Save Draft` wording for real saves.
- Exposed DM navigation on player-facing pages.
- Promoting DM Players and DM Characters as top-level DM pages.
